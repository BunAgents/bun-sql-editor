FAQ

Is my data safe? Do you store my credentials?

Yes, your data is safe. Connection credentials are stored exclusively in your browser's localStorage and are only ever sent to the local binary running on your own machine. Nothing is stored on any external server. The source code is fully public — you can audit every line at github.com/BunAgents/bun-sql-editor.

Why do I get a security warning on macOS / Windows?

The binary is not code-signed. Code signing certificates cost $300–500/year per platform. Since the project is open source, the most trustworthy option is to let you read the code and build the binary yourself. See Installation — Handle OS security prompt for instructions on bypassing the warning.

Can I use this as a team / shared tool?

Yes, but with caveats. If you run the binary on a shared server and expose it to the internet, anyone with the URL can connect to your databases. There is currently no built-in authentication. For team use, put it behind a VPN or a reverse proxy with HTTP Basic Auth (e.g. Nginx, Caddy, or Cloudflare Access).

Why not a cloud-hosted version?

A cloud-hosted version would require your database credentials to pass through a third-party server. We believe that is fundamentally a poor security trade-off for a database tool. See Why local? The case for a binary-first SQL editor for the full explanation.

Can I connect to a remote database?

Yes. The host field accepts any hostname or IP. Your local binary connects directly to the remote database over TCP. Ensure the database port is reachable from your machine (firewall rules, VPN, SSH tunnel if needed).

How do I use an SSH tunnel?

Set up the tunnel separately, then connect to the forwarded local port:

ssh -L 5433:db.internal:5432 user@bastion-host

Then in Bun SQL Editor connect to localhost:5433.

Does it work offline?

The UI shell is cached by the service worker and loads offline. Queries obviously require a live connection to the database.

Where is my data stored?

  • Connection configs — browser localStorage
  • Query history — browser localStorage
  • Query results — in-memory only, cleared on refresh
  • Nothing is stored on disk by the binary (it is stateless)

Can I run multiple instances on different ports?

PORT=3001 ./bun-sql-editor-macos-arm64
PORT=3002 ./bun-sql-editor-macos-arm64

Each instance is fully independent. Note that each browser window's localStorage is scoped to the origin (localhost:3001 vs localhost:3002), so connection configs are not shared between ports.

Does it support SSL / TLS connections?

Yes. Toggle the SSL switch in the connection dialog. For PostgreSQL this maps to ssl: true in the pg driver, which enables TLS without certificate verification by default.

How do I report a bug or request a feature?

Open an issue on GitHub Issues. Please include your OS, database type, and steps to reproduce.

Can I contribute?

Absolutely. Fork the repo, make your changes, and open a pull request. The codebase is vanilla TypeScript on the backend and vanilla JS on the frontend — no frameworks, no bundler step required for development.
