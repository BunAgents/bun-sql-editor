How we built ERD diagrams with vanilla JS and SVG

The ERD (entity-relationship diagram) feature lets you visualize foreign key relationships in your database schema. You get draggable table cards, bezier curves connecting related columns, and zoom/pan — all without a single third-party UI library.

Here's how it works.

The two-layer architecture

The ERD panel has two sibling layers that share the same coordinate space:

  • SVG layer — full-width, full-height, pointer-events disabled. Draws the FK relationship lines.
  • Canvas layer — absolute positioned div. Contains the table cards as absolute-positioned child divs.

Both layers are wrapped in a container that receives the zoom/pan transform via CSS transform: scale() translate(). When you pan or zoom, only the transform changes — the SVG paths and card positions don't need to be recalculated.

Drawing the bezier curves

Each FK relationship is drawn as a cubic bezier curve in SVG. To find the start and end points, we use getBoundingClientRect() on the specific column row in the source and target table cards:

function erdGetColAnchor(tableEl, colName, side) {
  const row = tableEl.querySelector(`[data-col="${colName}"]`);
  const rect = row.getBoundingClientRect();
  const wrapRect = erdWrap.getBoundingClientRect();
  const x = side === "right" ? rect.right - wrapRect.left : rect.left - wrapRect.left;
  const y = rect.top + rect.height / 2 - wrapRect.top;
  return { x: x / zoom, y: y / zoom }; // account for current zoom
}

The control points for the bezier are offset horizontally — cx1 = x1 + 80, cx2 = x2 - 80. This creates the characteristic S-curve shape. The path is then:

M x1 y1 C cx1 y1, cx2 y2, x2 y2

Zoom toward cursor

Zoom-toward-cursor is a common UX detail that most diagram tools get right — zooming in centers on your mouse position rather than the diagram origin. The formula:

pan.x = mouseX - (mouseX - pan.x) * (newZoom / oldZoom);
pan.y = mouseY - (mouseY - pan.y) * (newZoom / oldZoom);

This adjusts the pan offset so the point under the cursor appears to stay fixed while the diagram scales around it.

Draggable cards

Each table card is made draggable with a simple pointerdown / pointermove / pointerup handler. The key detail: mouse coordinates from the event are in screen space, but card positions are in diagram space (before zoom/pan). So we divide the delta by the current zoom level:

card.style.left = (startLeft + (e.clientX - startX) / zoom) + "px";
card.style.top  = (startTop  + (e.clientY - startY) / zoom) + "px";

After every drag move, we redraw all SVG lines — because the anchor points have moved.

The CSS hidden bug

One subtle bug took a while to find: the workspace panel (SQL editor + results) uses display: flex. Setting the HTML hidden attribute on it does nothing, because CSS display: flex overrides the browser's built-in [hidden] { display: none } rule.

The fix is explicit:

.workspace[hidden] { display: none; }

Without this, the SQL editor remained visible even when the ERD tab was active.

No libraries needed

The whole ERD feature — data fetching, layout, dragging, zooming, panning, line drawing — is about 200 lines of vanilla JS. SVG is well-suited for this: paths, markers (arrowheads), and transforms are all built-in. The browser handles the rendering.

Reaching for D3 or a canvas library would have added kilobytes of dependency for functionality the browser already provides natively.
